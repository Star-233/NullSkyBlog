## 核心概念

* **工作组处理器（WGP）：** RDNA 架构中每 2 个计算单元（CU）合并成一个 WGP，共享内存（LDS）就在 WGP 里面（RDNA 4 上每个 WGP 共 128 KB）。同一个线程块会被派到同一个 WGP 上执行，最多分到 64 KB 的 LDS。
* **货架（LDS）的作用域：** 只在同一线程块内部共享。**别的线程块看不到这一组的格子**（即使落在同一个 WGP 里也互不可见）；线程块之间要交接数据，只能经过显存。
* **同步屏障（`__syncthreads()`）：** 让**同一个线程块**里的所有线程都走到这一行，再一起往下执行；它同时带有内存栅栏，保证同步前写入 LDS 的数据在同步后对同组所有线程可见。别的线程块不会在这里等你。
* **数据竞争（Race Condition）：** 两个线程访问同一个位置，至少有一个在写，中间又没有同步。执行结果取决于谁先谁后，真卡上可能会时对时错。

## 为什么需要同步 & 写在哪里

一个线程块常包含多支小队（wavefront，例如 64 个线程分为小队 0：`0~31` 和小队 1：`32~63`）。同一支小队内的线程步调一致，但不同小队之间谁先走到哪一行说不准；因此取别人放进 LDS 的数之前，必须等整组都放好。

| **同步位置** | **执行结果** | **原因分析** |
| :--- | :--- | :--- |
| **放和取之间** | 正确（推荐） | 先各自放上货架，走到 `__syncthreads()` 等全组齐了，再安全读取其他线程放的数据。 |
| **删掉同步** | 发生数据竞争 | 先走完写入的小队直接去读，可能读到另一支小队还没写好的格子（模拟器会清零读到 `0`，真卡不会清零，结果随机出错）。 |
| **放在「放」之前** | 照样数据竞争 | 大家只是等齐后才开始放，放完没有再等就直接去取，先放完的小队依然会取早。 |

* **同步开销原则：** 每次同步，先到的小队都要停下来等最慢的那支小队。因此**只在取别人放的数据之前等一次**，别处不要多余同步。（若一个线程块只有 1 支小队，硬件上屏障等同于空操作，但代码里仍要写以兼容不同块大小。）

## 例子：组内数组倒序

任务：派 2 组、每组 64 个线程（或 4 组、每组 32 个线程），每组通过 LDS 把自己的那段数组倒序输出到 `out`，整组只同步一次。

```cpp
__global__ void flip(float* a, float* out) {
    __shared__ float s[64];             // 货架开 64 格
    int t = threadIdx.x;
    int i = blockIdx.x * blockDim.x + t;

    s[t] = a[i];                        // 把自己的数放上货架第 t 格
    __syncthreads();                    // 等整组都放好，再一起往下走

    out[i] = s[blockDim.x - 1 - t];     // 取对面那一格（用 blockDim.x 兼容 64/32 等不同组大小）
}
```

## 常见误区

* **能用 LDS 把跨线程块的整段数组倒过来吗？** 不能。例如 `block 0` 需要 `block 1` 搬进来的数据，由于 LDS 只在线程块内可见，跨块交接必须经过显存。
* **同一块 LDS 要复用放下一批数据时怎么办？** 在覆盖写入新数据之前，必须再同步一次，确保组内所有读者都已经把旧数据读完。
